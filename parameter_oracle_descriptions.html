Parameter and
oracle descriptions

For a problem in standard form, how are the objective and constraint functions actually specified? Two answers: a closed formula and some data — or query-only access to a black box. §4.1.4 draws the line between them, and the one direction that provably connects them.

§0where we are

§4.1.1–§4.1.3 defined the standard-form problem, its conventions, and equivalence transformations. One question remains, and it completes §4.1: for a problem in standard form (4.1), how are the objective and constraint functions actually specified? Two answers — a parameter description and an oracle model.

§1parameter problem description

Often the functions have an analytical — closed — form: a formula in x and some parameters.

For a quadratic objective \(f_0(x)=\tfrac12x^{\mathsf T}Px+q^{\mathsf T}x+r\), the specification is the coefficients \(P\in\mathbf S^n\), \(q\in\mathbf R^n\), \(r\in\mathbf R\) — the problem parameters (or problem data). B&V §4.1.4 · L6961–6970

This is a parameter problem description: the specific problem to solve — the problem instance — is fixed by giving the values of those parameters.

Σ

The formula \(\tfrac12x^{\mathsf T}Px+q^{\mathsf T}x+r\) is the family; a triple \((P,q,r)\) is one instance in that family. Change the numbers and you get a different problem to solve — same form, new data.

§2oracle model

Otherwise the functions are described by an oracle model — also called the black-box or subroutine model. Here we do not know f explicitly.

Instead we can: evaluate \(f(x)\) — and usually some derivatives — at any \(x\in\operatorname{dom}f\), i.e. query the oracle, usually at some cost (e.g. time); and use some given prior information about the function (e.g. convexity, a bound on its values). B&V §4.1.4 · L6971–6984

Concrete example: for an unconstrained minimize f, a subroutine returns f(x) and ∇f(x) at any queried x, but we have no access to its source.

!

The defining feature: in the oracle model we never really know the function — only its value (and some derivatives) at the points we have queried, plus whatever prior information we were given.

§3the distinction is not sharp

Two descriptions, but only one asserted direction between them:

  • induces
    Given a parameter description, we can construct an oracle for it — a routine that evaluates the required functions and derivatives when queried. So any parameter description induces an oracle.
  • specialize
    Most algorithms (Part III) work with an oracle model, but can be made more efficient when restricted to a specific parametrized family — exploiting the known data or structure.
  • no reverse
    B&V does not assert the reverse (oracle ⟹ parameter): query access alone need not reveal a parameter description unless extra structure is assumed.

B&V §4.1.4 · L6985–6990

!

Read this as one asserted direction plus a specialization remark — not a two-way equivalence.

§4expert lens — what to keep straight (diagnose)

E1Parameter description

A formula in x plus parameters / data — quadratic ⟹ (P,q,r). The problem instance is the parameter values.

E2Oracle model

Query-only access — evaluate f(x) and usually derivatives at chosen x, at a cost, plus prior information (convexity, bounds). You never see the function itself.

E3Not sharp (one direction)

A parameter description can be wrapped in an oracle; oracle algorithms specialize to a parametrized family for efficiency. The reverse — oracle ⟹ parameter — is not asserted.

E4Traps

The oracle is the one that evaluates via a subroutine, not the parameter description. The oracle returns f(x) / ∇f(x), not the minimizer or the closed form. Convexity here is prior information — not something asserted or required.

E5Scope

This is about problem description, still the general problem — the convex problem itself is §4.2.

Main points for quick review

Parameter description

Functions given by a closed-form formula in \(x\) and parameters/data; e.g. quadratic \(f_0=\tfrac12x^{\mathsf T}Px+q^{\mathsf T}x+r\) ⟹ data \((P\in\mathbf S^n,\,q\in\mathbf R^n,\,r\in\mathbf R)\). The instance is the parameter values.

Oracle model

Black-box query-only access — evaluate \(f(x)\) (and usually derivatives) at any \(x\in\operatorname{dom}f\), at a cost, plus prior information (convexity, bounds). We never know the function itself, only values at queried points.

Not sharp

A parameter description can be made into an oracle (that direction only); oracle algorithms specialize to a parametrized family for efficiency. Query access alone need not reveal a parameter description.
